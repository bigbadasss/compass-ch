# Life OS 数据定义

这些定义是应用和测试必须遵守的数据契约。

## 权威数据来源

Markdown 笔记及其属性是唯一权威来源。Life OS 不维护第二套任务或日记数据库。缺失配置代表数据不可用，不代表零分，也不得自行创造问题。

## 努力评分

- 有效分数是 1 到 10 的有限数字。
- 布尔值、数字字符串、超出范围的数字和缺失值都不是有效分数。
- 当日平均值是当天有效问题分数的算术平均。
- 时间范围平均值是各个“有评分日期平均值”的平均，不把所有答案混在一起计算。
- 无评分日期不进入平均值，同时必须显示有评分日期数量。
- 问题集合变化后，前后平均值含义可能不同，不应假装完全可比。

## 习惯

| 存储值 | 含义 | 已记录 | 已完成 |
| --- | --- | --- | --- |
| `true` | 完成 | 是 | 是 |
| `false` | 明确未完成 | 是 | 否 |
| 缺失或空白 | 未记录 | 否 | 否 |
| 其他值 | 无效 | 否 | 否 |

习惯完成率等于完成次数除以有效记录次数。缺失日期不得自动计为失败。

## 任务

任务流是对指定文件夹中任务行的只读索引。代码块中的 Markdown 示例不算真实任务，带 `example` 标签的文件不进入正式任务流。截止日期、计划日期和优先级是独立字段。

点击任务应打开来源行，不得修改任务或重复规则。

## 示例与部分数据

分析中是否包含示例必须明确显示。部分结果不能被描述为完整结果；没有索引到任务不等于证明没有任务。

## 生命领域与图谱

生命领域读取最近一篇有效季度回顾中的数字评分。它们是个人反思，不是临床或客观测量。Brain 的脑形位置和解剖线条是装饰，只有已解析链接构成关系边。

## 测试证据

合成测试使用虚构数据，只能证明逻辑在测试环境中通过，不能证明真实 Obsidian、移动端、AI 登录、备份恢复或发布流程已经成功。
